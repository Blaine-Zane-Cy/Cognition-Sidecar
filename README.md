# 认知掌控侧车 (Cognition Sidecar)

**保卫你在 AI 时代的控制权。**

![License](https://img.shields.io/badge/License-AGPL--3.0-blue) ![Platform](https://img.shields.io/badge/platform-Windows%2010%2F11-lightgrey) ![Python](https://img.shields.io/badge/python-3.11%2B-informational)

一个跑在你电脑上的本地工具：它不改造任何工作 Agent，而是坐在旁边，
帮你在 AI 产出洪流中保住三样东西——**判断的依据、决策的位置、意志的注入**。

---

## 为什么我造了它

我是一个有很多宏大想法的创造者。 idea 从来不缺——缺的是把 idea 落地时，
对每一个细节的掌控力。

当我把"深度领域、长链路的复杂任务"交给 AI Agent 时，我发现一件事：
**人类的认知带宽，是整条流水线上最先崩溃的环节。**

我能提出绝佳的构想，能判断大方向对不对。但当 Agent 返回一份几千字、
几十个步骤、引用了我并不熟悉的领域细节的产出时，我没有能力逐条核对。
我看得越多，把握得越少；交出去的越多，剩下的越少。到最后，
所谓"确认"，往往只是点了一下"接受"。

这不是我个人能力的问题。这是**全人类在面对一个产出速度远超理解速度的
智能体时，普遍存在的"认知掉线"**——工具越来越强，人的掌控感反而
越来越虚。我们能做的，要么是焦虑地逐字审查（然后被耗尽），
要么是放弃审查（然后失去控制权）。

所以我不试图造一个更聪明的 Agent 来解决这个问题——那只会让掉线更快。
我造的是一副**认知外骨骼**：它不替我思考，它把我的思考重新放回驾驶座。

## 核心宣言

> **我们不造更强的 Agent。**
> 我们造保护人类决策权、理解权和意志注入的"掌控侧车"，
> 让掌控力回归人类。

方向盘始终在你手里。侧车只负责给你依据和选项，
接受还是驳回，由你按下按钮。

## 它是什么

把 AI Agent 吐出来的东西丢给它，它会做三件事：

1. **结果程度卡** —— 把一份含糊的"我完成了"翻译成你能快速判断的结构：
   完成度 / 确定性 / 疑点 / 偏差 / 下一步。你不需要读完全文就知道该信几分。
2. **偏好规则库** —— 你的每一条模糊不满（"我要结论先行""这个别再让我确认"）
   都能沉淀成一条可编辑的规则。下次审批时它会告诉你：**"我是按第 N 条规则
   判的"**。你的判断标准会积累，而不是每次重新解释。
3. **结构化委托卡** —— 澄清之后，把你的意图整理成一张可以直接复制给
   任何工作 Agent 的委托卡。人负责想清楚，卡片负责不被曲解。

## 四大护城河（设计内核）

### 1. 树状决策：主干 + 平行分支

一次审阅是一条主干对话。讨论中冒出的每个疑点、每条待办，都可以
**分裂成一支平行分支**，独立展开细聊——聊完一键合并回主干，
结论自动回填，分支关闭。多个问题并行推进，互不串台，
也永远不会把一场对话搅成一锅粥。

### 2. 原文精准锚点：每个结论都能跳回出处

AI 说"原文第 3 段有问题"，你就应该能**点一下跳回原文第 3 段**。
侧车对每个结论都记录它在原文中的精确位置和引用片段，
点击即可回溯验证。**不信任任何转述，包括侧车自己的**——
这是防幻觉的最后一道闸。

### 3. 上下文精简：3 万字原文，不塞给模型

追一处细节不需要把整份文档喂给模型。侧车用四层预算
（委托卡全文 → 锚点上下文 ±500 字 → 全文骨架 → 最近 6 轮对话）
把上下文裁到刚好够用，超限就按序裁剪。而且每次请求都附一份
**"上下文回执"**，明明白白告诉你这次到底给了模型什么——
你连"它偷看了什么"都有权知道。

### 4. 个人偏好规则库：判断标准会复利

规则不是配置文件，是资产。每条规则记录它被命中了多少次、
影响了哪些判断。换一个项目、换一台机器，规则库跟着你走——
你的品味和标准，不会因为换了工具而清零。

## 快速开始

### 方式一：免安装（Windows 普通用户，推荐）

到 [Releases](../../releases) 页面下载 `Cognition-Sidecar-vX.X.X-win64.zip`，
解压后**双击 `启动.vbs`** 即可。

- 不需要装 Python、Node，不需要联网（用真实模型时才需要 API Key）；
- 窗口可以拖动、缩放、置顶，像一个小挂件悬浮在桌面；
- 想在浏览器右侧边栏用？把 `sidepanel-extension` 文件夹以"加载已解压的
  扩展程序"方式装进 Chrome/Edge 即可。

### 方式二：源码运行（开发者）

```bash
pip install -r requirements.txt

python demo.py                    # 不开界面，跑通整个闭环并自检
python -m streamlit run app.py    # 打开完整界面（默认 http://localhost:8501）
python desktop_app.py             # 桌面悬浮窗形态
```

- 窄栏（浏览器 sidePanel）模式：`http://localhost:8501/?embed=true&narrow=1`
- 想接真实模型：在界面「我的 → 模型与设置」填入 OpenAI 兼容 API Key；
  不填则使用内置演示替身（mock），全流程依然可跑。

## 隐私与安全

- **全部本地运行**：数据存在本机 SQLite（`data/app.db`），没有遥测、没有云端账号；
- **API Key 与数据分离**：Key 单独存放在 `data/secrets.json`（已被 `.gitignore`
  排除），永远不进数据库、不随代码分发——因为我们相信"可导出"不该等于"会泄露"；
- **发布包不带任何数据**：Release 附件里的独立版是干净起步的，
  你的规则库、会话、Key 都只在你自己的机器上。

## 项目结构

```
app.py                  Streamlit 界面入口
desktop_app.py          桌面悬浮窗（pywebview + Win32 无边框/拖拽/缩放）
core/                   业务内核：审阅、分支、锚点、规则、上下文预算
ui/                     页面组件（宽屏 / 窄栏 / 400px 挂件自适应）
sidepanel-extension/    Chrome / Edge 侧边栏扩展（MV3）
docs/                   设计实录与开发过程文档
seeds/                  演示种子数据
```

更多实现细节（锚点如何定位、分支如何防迷失、上下文四层预算如何裁剪）
见 [docs/开发实录.md](docs/开发实录.md)。

## 已知限制（别当成完成品）

- 以 Windows 为主场（悬浮窗依赖 WebView2，Win10 1903+ / Win11 自带）；
- 真实模型调用要求 OpenAI 兼容接口；
- 分支合并后的结论回填是单向的：合并后主干已有结论，分支不可逆；
- 这是 v1.0.0，粗糙的地方一定有——欢迎用 Issue 告诉我哪里硌手。
