# 方案评估：脱离 agent 环境的独立桌面挂件

**委托卡 v1 · 2026-11-10 · 本轮只评估，不改造**

---

## 0. 结论（先给）

**推荐方案 A：自带便携 CPython + 干净依赖 + 源码原样跑，换一个 `.vbs` 无黑窗入口。**

理由不是"简单"，是架构决定的：现有挂件是**双进程**——`desktop_app.py` 拉起一个 Streamlit 本地服务，再用 pywebview 套一个窗口。冻结工具（PyInstaller）对"Python Web 服务器 + 原生窗口"这种结构不友好，社区明确不推荐。方案 A 本质是**复制**，不改一行业务代码、不引入构建链，零构建风险，最贴合"自用工具"。

只有当验证用的目标机属于 §3 那几类"可能连 WebView2 都没有"的系统时，才升级到方案 C。

---

## 1. 现状：到底被什么绑住了

| 依赖 | 现在从哪来 | 独立运行怎么给 |
|---|---|---|
| CPython 3.13.12（`python.exe` / `pythonw.exe`） | `C:\Users\<user>\.workbuddy\binaries\python\versions\3.13.12` | 随包复制，**64 MB**（无 `pyvenv.cfg`，是标准安装，可直接搬） |
| streamlit 1.67 + 传递依赖 | 同环境 `site-packages` | 随包，**343 MB / 9550 文件**（实测） |
| pywebview 6.2.1 + pythonnet 3.2.1 | 同环境 | 随包（含在 343 MB 里） |
| **WebView2 Runtime** | 系统组件，本机 `157.0.4341.42` | **不能随 Python 包一起给**，见 §3 |
| .NET Framework 4.8（pythonnet / WinForms） | 系统（Win10 1903+ / Win11 自带） | 视为系统基线 |
| VC++ 2015–2022 运行库（numpy / pyarrow 的 DLL） | 系统；解释器目录已带 `vcruntime140.dll` | 绝大多数机器已有，列为验证项 |
| SQLite | Python 标准库 | 无需处理 |
| `data/app.db`、`gadget.json`、日志、`secrets.json` | `ROOT / "data"` | ✅ 已经是路径无关 |

**三处 agent 环境耦合，必须拆掉：**

1. `data/find_python.bat` — 按名字/能力探解释器，候选里硬编码 `%USERPROFILE%\.workbuddy\binaries\python\versions\*`。这是"依托 agent 运行"最直接的痕迹，独立版应整个删掉，入口固定指向包内 `runtime\`。
2. `desktop_app.py:234 console_python()` — 从 `sys.executable` 推导同目录的 `python.exe`，再用 `-m streamlit` 起子进程。方案 A 天然可用（runtime 里两个 exe 都在）；方案 B 会失效。
3. `启动-桌面挂件.bat` — 由 `cmd.exe` 解释，双击**必然出现控制台窗口**（`@echo off` 只隐藏文字，不隐藏窗口），只是闪得快。**不满足成功标准 5。**

## 2. 三个方案

### A · 绿色便携包（推荐）

```
认知掌控侧车/
├─ 启动.vbs                 ← 双击入口：wscript，0 窗口，路径自适应
├─ 创建桌面快捷方式.vbs     ← 可选，生成 .lnk
├─ runtime/                 ← CPython 核心 64 MB
│   ├─ python.exe / pythonw.exe / python313.dll / DLLs/ / Lib/
│   └─ Lib/site-packages/   ← 只放 requirements 的干净依赖 343 MB
├─ app.py / core/ / ui/ / desktop_app.py / .streamlit/config.toml
└─ data/                    ← 运行时生成（app.db / gadget.json / 日志）
```

**打包流程**（约 10 分钟，纯文件操作，无编译）：

1. 复制 CPython 核心；可去掉 `include/`、`libs/`、`Scripts/` 省约 27 MB。
2. 建干净依赖：`pip install --target runtime/Lib/site-packages -r requirements.txt`（构建机联网一次），或按各包 `RECORD` 从本机精确挑 43 个 distribution 复制（**构建也全程离线**）。
3. 复制源码（`core/` + `ui/` 纯 `.py` 共 269 KB）。
4. 删 `data/find_python.bat`；新增 `启动.vbs`：

```vbscript
Set fso = CreateObject("Scripting.FileSystemObject")
here = fso.GetParentFolderName(WScript.ScriptFullName)
Set sh = CreateObject("WScript.Shell")
sh.CurrentDirectory = here
sh.Run """" & here & "\runtime\pythonw.exe"" """ & here & "\desktop_app.py""", 0, False
```

（`0` = 隐藏窗口，`False` = 不等待；`here` 由脚本自身位置推导，换目录/换机器都不用改。）

5. 验收：改名 → 换路径 → 断网拷贝 → 双击。

| 项 | 值 |
|---|---|
| 目标机要求 | Win10 1903+ / Win11 **x64**，系统自带 WebView2 + .NET 4.8。不需 Python、Node、联网、管理员权限 |
| 产物体积 | **约 410 MB / 约 1.1 万文件**（64 + 343 + 1，实测口径）。zip 压缩后约 130–170 MB，但委托卡要的是"拷贝文件夹"，按未压缩算 |
| 维护成本 | **最低**。改功能 = 覆盖几个 `.py`；升级 streamlit = 重跑一次 pip；没有 spec、没有构建产物、没有二次调试 |

---

### B · PyInstaller `--onedir` 冻结

**流程**：写 `.spec` → `--collect-all streamlit`、`--collect-all pywebview`、手写 `hiddenimports`、`datas` 带上 `app.py` / `core/` / `ui/` / `.streamlit/config.toml` → `pyinstaller --windowed` → 产出 `认知掌控侧车.exe` + `_internal/`。

**两个绕不过去的改造**：

- `ensure_server()` 现在是 `Popen([console_python(), "-m", "streamlit", "run", "app.py"])`。冻结后 `sys.executable` 是 exe，`console_python()` 拼不出 `python.exe`，子进程起不来。要么把 Streamlit 改成同进程 `streamlit.web.bootstrap.run()` 起线程，要么再冻一个 `streamlit.exe` 当第二入口。**这是改启动逻辑，不是纯打包。**
- Streamlit 的前端静态资源、`config.toml` 必须从 cwd 读取、动态 import、`rpds` 等 hidden import —— 都是社区已知坑（Streamlit 官方论坛 2025 年多例；GitHub 上甚至有项目专文写"Why PyInstaller is not recommended for Streamlit Apps"）。

| 项 | 值 |
|---|---|
| 目标机要求 | 同 A（WebView2 / .NET 仍需），另需允许 exe 运行 |
| 产物体积 | **估算 300–400 MB**（`.pyc` 压进 PYZ，但 pyarrow/pandas/numpy 的 DLL 原样保留）—— **估算，未实测**，本轮不构建 |
| 维护成本 | **最高**。每次改代码重跑 2–5 分钟构建；streamlit 一升级可能破坏 spec；出问题要读 bootloader 日志 |

**判断：不推荐。** 省几十 MB，换来一条持续要维护的构建链，对自用工具不划算。唯一值得选的场景是你坚持"文件夹里必须有一个 `.exe`"。

---

### C · A + 内置 WebView2 Fixed Version（严格版）

在 A 基础上，把微软 **Fixed Version** 运行时作为**纯文件**随包（官方下载，解压即用，不写注册表、不弹 UAC、不联网），启动时设 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 指向包内目录。不改功能、不改外观。

| 项 | 值 |
|---|---|
| 目标机要求 | **只要 Win10/11 x64 + .NET 4.8，连系统 WebView2 都不需要**。唯一能 100% 覆盖委托卡"从未装过任何运行时"最严格解读的方案 |
| 产物体积 | **约 660–730 MB**（A 的 410 + Fixed Version 250–320，后者为微软/第三方文档口径，未实测） |
| 维护成本 | 和 A 一样低，但多一个 250 MB+ 二进制目录；Fixed Version 不自动收安全更新，要自己换版本 |

## 3. 那个必须说清的隐藏依赖：WebView2

**事实**（微软文档）：Evergreen WebView2 Runtime **预装在所有 Win11 设备**上；微软也已把它推送到所有符合条件的 Win10 设备。本机实测版本 `157.0.4341.42`（HKLM 注册表）。它**不是开发运行时**，是系统组件——所以"从未装过 Python/Node 的干净机器"通常**并不等于**"没有 WebView2"。

**边界条件**：Windows 10 LTSC、企业精简版、Server Core、全新离线安装且从未联网的机器，可能确实没有。

- 目标机是普通家用 Win11 / Win10 → **A 足够**
- 目标机是 LTSC / 精简系统，或你要求"绝对零假设" → **C**
- 建议 A 也带一句 10 行的检测：缺 WebView2 时弹一句人话提示，不自动安装（自动装会越界到"需要预备/管理员权限"）。

**不能用 IE/mshtml 当降级**：pywebview 6 的 mshtml 后端走 IE11 引擎，跑不了 Streamlit 的现代前端。

## 4. 五条成功标准逐条对照

| # | 标准 | 现状 | 需要的动作 |
|---|---|---|---|
| 1 | 干净机断网双击能显示 | A/C 满足（前提见 §3），B 同前提 | 真机验证必须你来做；我这边没有干净 VM，只能给检查清单 |
| 2 | 不依赖 agent、不报错 | `find_python.bat` 是耦合源 | 删掉，固定指向 `runtime\`；`check_deps()` 用包内解释器继续生效。**注意**：断网时真实 LLM 调用本来就用不了（`base_url` 指向外部 API，provider 回落 mock），这是产品固有限制、不是打包引入；标准 2 说的"唤起悬浮窗、显示内容"不受影响 |
| 3 | 路径无关 | **已基本满足**：`ROOT = Path(__file__).resolve().parent`、bat 已有 `cd /d "%~dp0"`、db/状态都在 `ROOT/data` | 入口换成按 `WScript.ScriptFullName` 推导的 `.vbs`。**不要用 `.lnk` 当文件夹内入口**——`.lnk` 写死绝对路径，换目录即失效 |
| 4 | 能生成桌面快捷方式，效果一致 | 系统"发送到桌面快捷方式"即可 | 用 VBS 建 `.lnk` 指向 `启动.vbs`；关键是 `.lnk` 的"起始位置"落在文件夹（现有 `cd /d "%~dp0"` 是双保险） |
| 5 | 无黑窗、无需敲命令 | **现有 `.bat` 不满足** | A/C 用 `.vbs`（wscript 隐藏窗口）；B 用 `--windowed` exe |

## 5. 本轮明确不做

安装包、自动更新、代码签名、改功能与外观、托盘图标、多屏适配、8501 端口冲突处理、压缩包分发、目标机预装 Python/Node/联网。

## 6. 数字口径

- **343 MB / 9550 文件** — 本机按 `requirements.txt` 实测 `pip install --target` 的结果（最新 streamlit 系列）。对照：本机完整 `site-packages` 是 799 MB，多出来的 scipy/cv2/playwright/sklearn 是 WorkBuddy 自己的包，与本工具无关，不随包。
- **64 MB** — `sys.base_prefix` 排除 `site-packages` 后实测。
- **269 KB** — `core/` + `ui/` 纯 `.py`。
- **250–320 MB（Fixed Version）**、**300–400 MB（方案 B）** — 文档口径与估算，**未实测**；本轮不构建任何产物。
