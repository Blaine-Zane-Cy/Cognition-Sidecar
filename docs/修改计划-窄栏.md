# 修改计划 · 窄栏模式（`?embed=1`）

> 目标：让同一套代码在浏览器右侧 1/3（360–560px，主攻 400–480px）宽度下，结果卡对话、胶囊按钮、输入框都不横向溢出、不挤成两字一行。
> 不改业务逻辑一行。宽屏模式像素级不变。

---

## 一、三个定死的技术决定

### 1. 用 CSS 控制宽度，**不动** `set_page_config`

`st.set_page_config` 必须是第一个 Streamlit 命令，且同一个会话里**不能再改**。如果按 `layout="centered"` / `"wide"` 在两模式间切换，用户点了 URL 里的 `?embed=1` 之后想退回宽屏，就得重启会话。

所以：`layout="wide"` 永远不变，窄栏完全由一层注入的 CSS 决定：

```css
[data-testid="stMainBlockContainer"]{ max-width:100%; padding:.5rem .6rem 1.4rem; }
```

好处：`?embed=1` 是纯表现的开关，加参数/去参数刷新即切换，零副作用。

### 2. `?embed=1` 的语义是「**窄栏 + 无壳**」，不是「另一个应用」

- 无壳 = 隐藏 Streamlit 的 header、toolbar、deploy 按钮、MainMenu、footer、彩虹条、侧边栏。
- 功能不减：三个页面照样能进（导航换成顶部一排 `segmented_control`），设置照样能改。
- 参数只认这几个值：`1 / true / yes / on`（大小写不敏感）。其它值一律当宽屏，避免 `?embed=0` 反而进窄栏的坑。

### 3. 列布局靠**代码分支**，不靠 CSS 硬掰

`st.columns` 在 400px 下即使 `flex-wrap` 换行，按钮宽度和文字对齐还是会烂（按钮 4 颗挤一行 = 每颗 88px，"这次收了"四个字就撑满）。23 处 `st.columns` 里，只有 9 处真正需要改，其余在窄栏下两列依然可读（2 列在 400px = 每列 190px，够用）。

统一入口：新模块 `ui/layout.py`

```python
def narrow() -> bool            # 读 st.query_params，每次调用现读，不缓存
def cols(spec, **kw)            # 窄栏 → 竖向堆叠的等宽容器；宽屏 → st.columns 原样透传
def pair()                      # 两列；窄栏下需要时仍返回真两列（按钮并排用）
```

业务代码只改调用点，不写 `if narrow():` 的散装分支。

## 二、要改的文件与逐处改法

### 新增：`ui/layout.py`（约 150 行）

### `app.py`（改约 20 行）

```
set_page_config(layout="wide")   ← 不动
layout.inject_css()              ← 新增，紧跟其后
if layout.narrow():
    顶栏：segmented_control(工作台/结果卡/规则库/设置, key="nav")
          右侧一行 12px 灰字：演示替身 · 规则 3 条

    现有侧边栏原样
```

注意：侧边栏的 `st.radio(key="nav")` 与窄栏的 `segmented_control(key="nav")` **不同时存在**，key 不冲突；两模式切换走 URL 刷新，是同一次新会话。

## 三、窄栏 CSS 明细（`NARROW_CSS` 覆盖的东西）

按「先砍壳、再砍空、最后压字号」三层写，选择器以实测 DOM 为准（下面 6 个 testid 我会先跑一次 DOM 探针确认，Streamlit 1.67 的命名与旧版有出入）：

1. **砍壳**：`stHeader`、`stToolbar`、`stDecoration`、`stStatusWidget`、`MainMenu`、`footer`、侧边栏及其折叠按钮 → `display:none`
2. **砍空**：`block-container` padding `0.5rem 0.6rem 1.4rem`、`max-width:100%`；`stVerticalBlock` gap `.45rem`；`stHorizontalBlock` gap `.4rem`；`hr` margin `10px 0`
3. **压字号**：`html` 基准 16→14px；正文段落 13.5px/1.72；h1 20px、h2 17px、h3 15px、h4 14px；`.stCaption` 11.5px
4. **不溢出**（最关键的四条）：
   - `pre{white-space:pre-wrap!important;word-break:break-word}` —— 委托卡/原文对照在窄栏里必须**折行**，不能横向滚动条
   - `.stMarkdown p, .stMarkdown li{overflow-wrap:anywhere}` —— 长英文串（URL、包名）不顶破气泡
   - `stPopoverBody{max-width:calc(100vw - 24px)}` —— 依据 popover 在侧栏里不能超出屏幕
   - `stCode{overflow-x:auto}` 保留（代码块内部允许滚，但**不许把外层页面顶宽**）
5. **气泡收紧**：`stChatMessage` padding `8px 10px`、圆角 10px、`gap .4rem`；**窄栏隐藏头像**（省 40px 横向），助手气泡改左侧 2px 竖线区分
6. **触控尺寸**：按钮 `min-height:34px`（窄栏鼠标精度低，32px 以下的按钮容易点空）

## 四、验收口径（怎么算"改对了"）

### 硬指标（Playwright 断言，非肉眼）

| 项 | 阈值 | 怎么测 |
|---|---|---|
| 横向溢出 | `document.documentElement.scrollWidth <= clientWidth + 1` | 420×860 与 480×900 两个视口，走完 6 个界面各断言一次 |
| 首屏信息量 | 开场白 + 胶囊全部可见，不需要滚动 | 截图高度比对：数字条顶端到最后一颗胶囊底端 ≤ 视口高 - 100px |
| 单行按钮数 | ≤ 2 | 遍历 `button` 的 boundingBox，同一 `top` 值上不超过 2 个 |
| 输入框 | 宽度占满容器，右边缘距容器右边 ≤ 2px | boundingBox 比对 |
| 文字溢出 | 无 `scrollWidth > clientWidth` 的段落 | 遍历 `.stMarkdown p` |

## 五、需要你点头的三处取舍

1. **导航换成顶部 `segmented_control`**，而不是做个汉堡菜单弹窗。理由：4 个页面、扁平结构，一排能放下；弹窗多一次点击。代价是窄栏顶部多占约 40px 高度。
2. **窄栏隐藏聊天头像**。理由：侧栏宽度里 40px 很贵，头像不承载信息。代价：少一点"像人"的感觉——用左侧竖线补。
3. **槽位面板在澄清阶段默认收起**。理由：窄栏首屏放不下"对话+槽位"两件事，而澄清时你主要看对话。代价：想看槽位进度要多点一次（展开后仍完整）。

## 六、路线 1（sidePanel 扩展）的接口约定

窄栏这步做完，扩展只是"打开一个 URL"，所以先把契约定下来，代码下一步再给：

- 入口 URL：`http://localhost:8501/?embed=1`
- 扩展形态：`manifest_version: 3`，`permissions: ["sidePanel"]`，`side_panel.default_path: "panel.html"`
- 图标点击 → `chrome.sidePanel.open()`（`sidePanel.setPanelBehavior({openPanelOnActionClick:true})` 一行搞定）
- `panel.html` 只是 `<iframe>` 还是直接导航？**直接导航**（`location.replace`）：iframe 会被 Streamlit 的 `X-Frame-Options` 拦，也带不进 `?embed=1` 的兄弟状态
- 服务没起来时，`panel.html` 需给自己留一个兜底：先探测 `localhost:8501/_stcore/health`，不通就显示"先把服务跑起来"＋一键重试
- Chrome 114+ / Edge 114+ 均支持；低于此版本给降级说明（`window.open` 弹独立窗口）

## 八、执行记录（实际落地时，与上面计划的四处差异）

### 1. `?embed=1` 走不通，改成 `?embed=true&narrow=1`

计划里假设 `?embed=1` 能被 Python 读到。实测不行：`embed` 是 Streamlit 的保留参数，
它在送给后端的 `query_params` 里被**整个吃掉**（`st.query_params` 永远是 `{}`），
而且只有 `=true` 才会触发它的原生嵌入模式。所以：

- `embed=true` → 交给 Streamlit，隐藏它自己的 Deploy/菜单；
- `narrow=1` → 我们自己的开关（`side=1` / `panel=1` 是别名）。

### 2. 真正的拦路虎不是 `pre`，是 Streamlit 的 640px 断点

计划里把 `pre` 折行列为"最重要的四条"之首。它确实重要（`pre > code` 自带
`white-space:pre` + `inline-block` + 内容宽度，只压 `pre` 会变成裁字而不是折行），
但更狠的是：**Streamlit 在 640px 以下给每个 `stColumn` 加 `min-width:calc(100% - 21px)`**，
把所有列无条件竖排。420px 下连两颗按钮并排都做不到，代码里写多少 `st.columns(2)` 都没用。

一行 CSS 解决：`[data-testid="stColumn"]{min-width:0 !important}`。
这条不在原计划里，是量 DOM 量出来的（`colMinW: calc(100% - 21px)`）。

### 3. `layout.cols(2)` 传整数时的 bug

`st.columns` 接受整数，我的窄栏分支写成了 `for _ in spec` → `TypeError: 'int' object is not iterable`，
在委托卡编辑区炸出来。已改为按 int / 序列分别取数量。

### 4. 顺手修了一个宽屏也有的旧 bug

结案留言（`kind="note"`，"这次收了" / "理由已入库"）在审阅对话里被当成普通助手消息，
但它没有 `refs`，于是渲染成一个**空白气泡**。窄栏里这个空块格外扎眼，顺手修了：
note 改成一行灰字，宽屏同样受益。
