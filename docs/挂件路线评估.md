# 从"独立网页"到"侧边挂件"：三条路线的成本与取舍

> 只做评估，没有动代码。所有数字都是按当前这份代码（Streamlit 1.67 + 4 个页面 +
> `core/` 业务层）估的，不是通用经验值。

---

## 0. 先认清约束：现在这套东西是什么形状

| 事实 | 对路线选择的影响 |
|---|---|
| UI 是 Streamlit，本质是**一个跑在 localhost 的 Web 服务器**（默认 8501） | 任何"挂件"只要能显示一个网页，就能复用 100% 的 UI |
| 业务状态全在 SQLite，`session_state` 只放 `session_id` 和展开态 | 挂件换了容器，数据不会丢；但**换容器会丢 `session_id`**，需要显式存到 URL |
| 4 个页面里，工作台是纵向长流（澄清 → 委托卡 → 贴结果 → 对话审阅） | 窄栏（~400px）下必须换布局，否则 `st.columns` 会挤成一团 |
| `core/drafts.py` 里 `import streamlit` | 想走"无 UI 的 API"路线，这一层要先解耦（见第 4 节） |
| 没有登录、没有多用户 | 挂件不需要处理鉴权，省掉一大块工作量 |

**一个所有路线都要先做的事：窄栏模式（`?embed=1`）。**
把侧栏导航收成一行胶囊、页面改单列、字号/间距压紧、`session_id` 写进 URL query。
大约 40–60 行，改 `app.py` 加一个 `ui/embed.py`。
不做这一步，无论挂在哪里都是一块被压扁的宽屏网页。

---

## 1. 三条路线对照

| | 路线 1 · 浏览器侧边栏 | 路线 2 · 桌面悬浮窗 | 路线 3 · 剪贴板 + 热键 |
|---|---|---|---|
| 形态 | 浏览器原生侧栏，和 Agent 页面**并排** | 一个置顶小窗，浮在任意软件上方 | 没有界面，按热键唤起 |
| 复用现有 UI | 100%（iframe 本地 Streamlit） | 100%（WebView 指向同一地址） | 0%（没有 UI 可复用） |
| 需要新写的代码 | 扩展约 150 行 + 窄栏模式 | 启动器约 60 行 + 窄栏模式 | 监听/热键约 100 行 |
| 要装什么 | Chrome/Edge 114+，开发者模式加载解压扩展 | Python 依赖 `pywebview`；打包后是单个 .exe | 无（Python 脚本常驻） |
| 是否遮挡 Agent 页面 | **不遮挡**（浏览器自己分栏） | **遮挡**（置顶窗盖住一块） | 不适用 |
| 冷启动 | Streamlit 2–3 秒 | 同左（可让启动器预热） | 热键唤起 1 秒内 |
| 工程量 | **0.5–1 天** | **0.5 天**（打包成 exe 再 +0.5 天） | **0.5 天** |
| 主要风险 | 扩展权限、iframe 的 XSRF/存储隔离 | 单屏下遮挡、打包体积 200MB+ | 剪贴板隐私 |

## 2. 路线 1：浏览器侧边栏（推荐作为终局）

**关键实现选择：用 `chrome.sidePanel`，不要往 ChatGPT 页面里注入 iframe。**

- 注入 iframe 会被 Agent 站点的 CSP（`frame-src`）挡掉，而且页面改版就失效；
- `sidePanel` 是浏览器自己的一块面板，加载的是**扩展自己的页面**，不受目标站点 CSP 约束；
- 面板里再 `iframe` 指向 `http://localhost:8501` —— 扩展页面是安全上下文，
  且 Chrome 把 `localhost` 视为可信来源，不会被混合内容拦。

**需要你做的事**：装 Chrome 或 Edge（114+）→ 打开 `chrome://extensions` → 开启"开发者模式"
→ "加载已解压的扩展程序" → 选 `extension/` 目录。不需要证书、不需要上架。
（想免开发者模式就得打包 .crx 并签名，成本陡增，不建议现在做。）

**需要改代码的地方（合计 40–60 行）**：
- `app.py`：读 `st.query_params["embed"]`，`layout="centered"`、隐藏侧栏；
- 新 `ui/embed.py`：窄栏下的导航（一行 `st.segmented_control`）和页面路由；
- `session_id` 从 query 里读/写（否则在面板里刷新会回到"新建会话"）。

**启动方式**：`run_sidecar.bat` 起 Streamlit（保持常驻）→ 扩展面板直接连。
建议加 `--server.enableXsrfProtection=false`，避开 iframe 里的 XSRF 令牌问题（仅本地）。

**为什么它是终局**：只有这条路做到了"Agent 在左、侧车在右，谁都不遮谁"。
复制粘贴仍然走系统剪贴板，但你的视线和鼠标不需要离开同一块屏幕。

## 3. 路线 2：桌面悬浮窗（最快能用）

三个候选，差别只在"壳"：

| 方案 | 体积 | 开发量 | 备注 |
|---|---|---|---|
| **pywebview**（推荐） | exe 200–300MB | 半天 | Windows 直接用系统自带 Edge WebView2，`on_top=True` 就是置顶 |
| Electron | 150MB+ | 1 天 | 生态最熟，但为了一个窗口装半个 Chromium 不划算 |
| Tauri | 10MB 壳 + Python 运行时 | 2–3 天 | 要 Rust 工具链；Streamlit 作为 sidecar 打包，体积优势被 Python 吃掉 |

**现有 UI 需要重写多少：0 行。**
WebView 就是个浏览器，指向 `http://localhost:8501` 即可。唯一要做的还是那个窄栏模式
（窗口 420×900 时，宽屏布局会挤）。所以这条路线的真实成本是"窄栏模式 + 60 行启动器"。

**它的问题**：置顶窗会盖住 Agent 页面。单屏下你必须把 Agent 窗口缩小或横向滚动，
"不切屏"在视觉上成立、在注意力上不成立。**双屏时体验最好**（侧车常驻副屏）。

**打包**：PyInstaller 把 `app.py` + `core/` + `ui/` + 一个 `.bat` 打进 exe，
启动时先拉起 Streamlit 子进程、等端口就绪、再开窗、退出时回收子进程。
半天工作量里有一半是处理端口占用和进程清理。

## 4. 路线 3：剪贴板监听（只能是增强，不能是替代）

它没有界面，所以严格来说不是"挂件"。它解决的是**动作链太长**：

> 现在：复制结果 → 切窗口 → 切到工作台 → 点粘贴框 → Ctrl+V → 点「发起审阅」
> 之后：复制结果 → 按 Ctrl+Alt+J → 窗口已经打开、内容已经填好、只差点确认

**我建议不要做"无脑监听剪贴板"**：那等于在你的机器上常驻一个记录剪贴板的东西，
密码、验证码、私聊内容都会进日志。只做**热键触发时读一次**，读到的内容只进内存/草稿表。

顺带说一句：真要做 API 化（不走 UI，直接 `core.` 调），第一件事是把
`core/drafts.py` 从 Streamlit 里解耦（它现在依赖 `st.session_state`）。
这是路线 3 想做"纯后台"时的隐藏成本，不做就当没有。

## 5. 推荐顺序（按"多快能用上"排）

| 步 | 做什么 | 花多久 | 得到什么 |
|---|---|---|---|
| S1 | 窄栏模式 `?embed=1` | 2–3 小时 | 路线 1 和 2 的共同前置，也是手机上能用 |
| S2 | pywebview 悬浮窗 + 启动脚本 | 半天 | **当天就能不切屏**（遮挡版）；打包 exe 再 +半天 |
| S3 | Chrome 扩展 `sidePanel` | 0.5–1 天 | 真正并排、不遮挡，终局形态 |
| S4 | 全局热键唤起 + 剪贴板预填 | 0.5 天 | 把动作链压到"复制 + 一个热键" |

**如果只能选一条：选 S3（路线 1）。**
它比悬浮窗多花半天，但换来"不遮挡"和"和 Agent 同屏"，这才是这个产品想解决的痛点。
悬浮窗适合当过渡：今天就想用，就做 S2。

**不建议现在做的**：把 Streamlit 换掉、手写前端 + FastAPI。
那等于把 4700 行里的一半重写一遍，换来的只是体积和启动速度，跟"不切屏"没关系。

## 6. 三个路线都会碰到、需要提前定的细节

1. **`session_id` 的持久化**：现在靠 `st.session_state`。iframe 里刷新/切标签页会丢。
   建议：进入对话时把 `sid` 写进 URL query，启动时优先读 query。
2. **窄栏下的"首屏 30 秒"**：400px 宽时，5 段开场白会占两屏。
   窄栏模式要额外把段落折成 3 段（结论 / 疑点 / 待定），其余收进"展开"。
3. **端口与进程**：挂件必须能自己判断"Streamlit 已经在跑"，而不是每次开一个新的。
   做法：固定端口 + 启动前 `connect` 探测，失败才起进程。
